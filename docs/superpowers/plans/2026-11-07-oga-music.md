# OpenGameArt Soundtrack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Embervale's synthesised music with 17 user-chosen OpenGameArt tracks, one per game area, streamed lazily and crossfaded.

**Architecture:** One `<audio loop>` element per slot, created on first use, routed through `MediaElementAudioSourceNode` → per-track gain → `MUS.lift` (combat lift) → `MUS.gain` (volume + ducking, unchanged contract) → destination. `musicTick()` (already polled every 60 ms) detects slot changes via `wantTheme()` and runs an equal-power crossfade. The old oscillator engine is deleted.

**Tech Stack:** Vanilla JS + Web Audio, concatenated by `source/build.sh` into `index.html`; ffmpeg/ffprobe (`/opt/homebrew/bin`) for conversion; in-browser smoke test `source/test.js` (built to `/tmp/embervale_test.html`); Playwright MCP for runtime checks.

**Spec:** `docs/superpowers/specs/2026-11-07-oga-music-design.md`

## Global Constraints
- Slots (exactly 17): `title`, `town`, `r0`…`r11`, `abyss`, `boss`, `trial`.
- Licences: CC0 or CC-BY only. No CC-BY-SA, GPL, OGA-BY, NC.
- Files: `assets/music/<slot>.m4a`, AAC ~96 kbps stereo, loudness-normalised to −16 LUFS integrated (±1 LU).
- Crossfade ≈ 1.5 s equal-power. Combat lift = ×1.15 on `MUS.lift`.
- `MUS.gain` keeps meaning “music volume × .55, with ducking”: `setMusicVol` and `duckMusic` (`source/6v_audio.js:44`) stay unchanged.
- Failure of any track = silence for that slot, never a thrown error; retried on the next area change.
- Downloads are untrusted: each in its own empty scratch dir outside the repo; never run anything from inside it.
- Commits: no Co-Authored-By trailer (user memory). Don't push without the user's OK.

## Review Focus
1. **Opening `index.html` via `file://`**: `MediaElementSource` on a file URL is CORS-tainted and outputs silence. Expected: game still runs, no errors. Local testing is done over `python3 -m http.server`. Test in Task 3 (test build runs with missing files) + note in README.
2. **Rapid area flips** (town → floor → town within the 1.5 s fade): expected no stacked/doubled tracks, last slot wins. Test in Task 3 Playwright step.
3. **Returning to a slot**: expected the track restarts from 0 unless it was still fading out (then it continues). Test in Task 3.
4. **Autoplay blocked / AC suspended** (before first click): expected no error, music starts once `AC` is running. Covered by `musicTick` early-return; checked in Task 3 Playwright step on the title screen.
5. **Loop seam**: AAC priming can add a tiny gap at the loop point. Expected: acceptable; the user judges by ear in Task 4. Pick tracks marked “loop” where possible in Task 1.

- [ ] **Step 3: Implement** `source/6s_music.js` with the interfaces above. Routing: track `el` (`crossOrigin='anonymous'`, `loop=true`, `preload='auto'`) → `createMediaElementSource` → `g` → `MUS.lift` → `MUS.gain` → `AC.destination`. `el.onerror` and a rejected `el.play()` set `ok=false` (catch, never throw). On slot change: new track `g` ramps 0→1 and every other playing track 1→0 over 1.5 s using `setValueCurveAtTime` with sin/cos curves (64 points, starting from each gain's current value); a track whose gain has reached ~0 is paused. Entering a slot whose gain is < .01 sets `el.currentTime = 0` first; mid-fade it just continues. First start: `MUS.gain` targets `musicVol() * .55` (time constant .7). Each tick: `MUS.lift.gain.setTargetAtTime(MUS.combat ? 1.15 : 1, now, .5)`. Return early if `!AC || AC.state !== 'running'`.
